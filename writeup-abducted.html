Abducted

HackTheBox Medium red team | Linux · Samba | date
tl;dr

Write last. Shape: an unauthenticated Samba print-subsystem command injection (CVE-2026-4480) gives a shell as nobody; an rclone backup config holds an obfuscated password that decodes and is reused for scott; scott owns a wide-links Samba share that runs as marcus, abused to plant an SSH key and become marcus; marcus can restart smbd via a systemd drop-in + polkit rule, abused with ExecStartPre to make a SetUID bash and get root.

command-injection exposed-credentials priv-esc

01Enumeration

nmap (22/139/445), then SMB recon: null/guest session, share listing, and rpcclient for users. Note the bait — weak password policy + no lockout are there to tempt a pointless brute.

$ nmap -p- --min-rate 10000 IP
$ smbclient -L //IP/ -N          # HP-Reception, projects, transfer, IPC$
$ rpcclient -N IP -U ""            # enumdomusers -> scott

Key realisation to write up: projects/transfer deny guest, and the printer share is the only thing you can touch anonymously. That plus "box released straight to retired" points at a recent Samba CVE, not a brute-force.

02Foothold — CVE-2026-4480 (Samba print injection)

Explain the bug: the print-job name (%J) is passed to the shell unescaped. Show connecting to HP-Reception anonymously and printing a file whose NAME is a shell payload. Confirm execution with a ping, then swap for a reverse shell -> land as nobody.

SCREENSHOT — reverse shell as nobody

03Lateral to scott — credential reuse

From nobody, enumerate the filesystem. Cover /opt/offsite-backup: the rclone.conf with an obfuscated password, decoding it with rclone reveal, and reusing it for scott (su / SSH). Grab user.txt (redacted).

04Lateral to marcus — Samba wide-link abuse

Read /etc/samba/shares.conf: the transfer share is valid users = scott, force user = marcus, wide links = yes. Explain why that's exploitable: symlink /home/marcus into the share, access it over SMB as scott (running as marcus), drop an SSH authorized_keys, and log in as marcus.

05Privilege escalation to root — systemd drop-in + polkit

marcus is in the operators group, which owns the smbd.service.d drop-in dir and (via a polkit rule) can restart smbd. Write an ExecStartPre that copies bash to a SetUID binary, reload + restart smbd, run the SetUID bash with -p -> root. Redact root.txt.

SCREENSHOT — id showing uid=0 and redacted root proof

06Root cause & remediation

Samba print injection
CVE-2026-4480		 Patch Samba; avoid passing %J to a shell; disable unused printer shares.
Reused / recoverable creds rclone obfuscation isn't encryption; unique per-account creds; secrets management.
Samba wide links Disable wide links / insecure wide links; don't force-user across trust boundaries.
Writable systemd drop-in + polkit grant No group-writable unit dirs; scope polkit rules tightly; don't let a service restart become a root primitive.

07Takeaways

What this box drills: don't take the bait (weak-policy != brute-force), read release/retire timing as a CVE hint, and how a chain of small Linux/Samba misconfigs compounds into full compromise. What you'd do faster next time.
