Biohazard

TryHackMe Medium red team | Linux · web | 29 Jul 2026
tl;dr

A Resident Evil themed mansion crawl. The web app hides a trail of classical ciphers and layered encodings (Base64, Base32, Base58, Vigenère, ROT13, binary, hex) guarding a set of "crests" that combine into FTP credentials. FTP yields images and a GPG file; three key-images each hide a fragment (empty-passphrase steghide, appended data, embedded file) that rebuild the passphrase to the GPG and unlock the helmet key. From there a tar-archived medal gives SSH access, a final Vigenère (key albert) reveals the operator login, and sudo su walks it to root.

data-obfuscation steganography exposed-credentials priv-esc

As a big fan of the Resident Evil series, I had to try this room. It leans almost entirely on encoding/cipher recognition rather than memory-corruption exploits — which makes it a great drill for one specific skill: looking at a blob and knowing what it is before you try to open it.

01Enumeration

A full port scan turned up three services — FTP, SSH, and a web server.

$ nmap -p- --min-rate 1000 -T4 10.x.x.x
$ nmap -p 21,22,80 -sVC 10.x.x.x

21/tcp  open  ftp     (no anonymous login)
22/tcp  open  ssh
80/tcp  open  http    Apache/2.4.29   title: "Beginning of the end"

FTP and SSH both refused anonymous access, so the way in had to start on port 80. The site drops you at /mansionMain/ — no links, no buttons, nothing to click. First instinct on a dead page: read the source.

SCREENSHOT — view-source of /mansionMain/ revealing the /diningRoom/ hint

The source pointed to /diningRoom/, and that's the pattern the whole box repeats: each room hides a breadcrumb — in a comment, in an encoded string, or behind a cipher — that names the next room or hands you an item.

02The mansion — emblems & ciphers

/diningRoom/ gave up an emblem{[redacted]}. Placing it did nothing yet — but the emblem string itself looked oddly familiar, and refreshing the page then re-reading the source revealed a Base64 breadcrumb:

$ echo 'SG93IGFib3V0IHRoZSAvdGVhUm9vbS8=' | base64 -d
How about the /teaRoom/

Vigenère #1 — the shield key (key: rebecca)

Returning to the dining room after collecting the gold emblem produced a scrambled message that preserved word structure — the fingerprint of a keyed substitution cipher, not an encoding:

# ciphertext
klfvg ks r wimgnd biz mpuiui ulg fiemok tqod. Xii jvmc tbkg ks tempgf tyi_hvgct_jljinf_kvc

# Vigenère decode, key = rebecca (recovered elsewhere in the mansion)
there is a shield key inside the dining room. the html page is called the_great_shield_key

Browsing to that page handed over shield_key{[redacted]}.

the recurring lesson A hash-identifier is useless on all of this — none of it is a hash. These are reversible encodings and classical ciphers, and you identify them by their alphabet and structure: caps + 2–7 is Base32; mixed case with no 0/O/I/l is Base58; letters that keep their word spacing is a Vigenère/substitution cipher.

03The four crests → FTP credentials

Inserting the gem at /tigerStatueRoom/ started the main puzzle: four crests, each multi-encoded, that combine (crest 1 + 2 + 3 + 4) into one Base64 string. Each crest re-uses the encodings from the mansion — and the discipline that matters here is re-identifying every layer before decoding it, because the scheme changes between layers.

the trap "Encoded twice" does not mean "the same encoding twice." Decode one layer, then stop and inventory the output's alphabet again before choosing your next decoder. Auto-piloting Base64 twice is how you get garbage. 
# Crest 1  (encoded twice)  Base64 -> Base32
S0pXRkVVS0pKQkxIVVdTWUpFM0VTUlk9   -> base64 -> KJWFEUKJJBLHUWSYJE3ESRY=
KJWFEUKJJBLHUWSYJE3ESRY=          -> base32 -> RlRQIHVzZXI6IG

# Crest 2  (encoded twice)  Base32 -> Base58
GVFWK5KHK5WTGTCILE4DKY3DNN4GQQRTM5AVCTKE -> base32 -> 5KeuGWm3LHY85cckxhB3gAQMD
5KeuGWm3LHY85cckxhB3gAQMD                -> base58 -> h1bnRlciwgRlRQIHBh

# Crest 3  (encoded three times)  Base64 -> binary -> hex
MDAxMTAxMTAg... -> base64 -> "00110110 00110011 ..." -> binary -> "63 33 4d 36 ..." -> hex -> c3M6IHlvdV9jYW50X2h

# Crest 4  hex
gSUERauVpvKz... -> hex -> pZGVfZm9yZXZlcg==

Concatenated in order, the four fragments form one final Base64 string:

$ echo 'RlRQIHVzZXI6IGh1bnRlciwgRlRQIHBhc3M6IHlvdV9jYW50X2hpZGVfZm9yZXZlcg==' | base64 -d
FTP user: hunter, FTP pass: you_cant_hide_forever
what this really is Credentials "protected" by six stacked encodings — none of which is encryption. Anyone who reaches the crests can reverse the lot with no secret. Encoding is obfuscation, not security.

04FTP loot & steganography → helmet key

Logging into FTP with hunter pulled down three "key" images, a GPG file, and a note. The note set the objective: /hidden_closet/ is locked and needs the helmet key, and helmet_key.txt.gpg is encrypted with AES256 — so it's symmetric and wants a passphrase. That passphrase is split across the three images, each hiding its fragment a different way.

SCREENSHOT — FTP directory listing with the 3 images, the .gpg, and the note
# run the full ladder on EACH image: exiftool / strings / binwalk / steghide

# 001-key.jpg — steghide with an EMPTY passphrase (just press Enter)
$ steghide extract -sf 001-key.jpg      # blank passphrase
cGxhbnQ0Ml9jYW

# 002-key.jpg — fragment sitting in the plaintext strings
$ strings 002-key.jpg | head
5fYmVfZGVzdHJveV9

# 003-key.jpg — binwalk reveals embedded data
$ binwalk 003-key.jpg
3aXRoX3Zqb2x0
lesson paid for in time I burned a while throwing rebecca and other loot at 001 before learning its passphrase was blank. Rule for next time: on any steghide file, try an empty passphrase first (stegseek tests it instantly).

The three fragments are pieces of one Base64 string — decoding any single piece alone gives partial nonsense, which is the tell that they must be joined first:

$ echo 'cGxhbnQ0Ml9jYW5fYmVfZGVzdHJveV93aXRoX3Zqb2x0' | base64 -d
plant42_can_be_destroy_with_vjolt

That string is the GPG passphrase. Decrypting the file releases the helmet_key{[redacted]}, which unlocks /hiddenCloset/.

$ gpg --decrypt helmet_key.txt.gpg      # passphrase: plant42_can_be_destroy_with_vjolt

05Foothold — from medals to SSH

Two threads converge into the first shell. In the mansion, /studyRoom/ (behind the helmet symbol) held a sealed book that downloaded doom.tar.gz:

$ tar -xf doom.tar.gz
$ cat eagle_medal.txt
SSH user: umbrella_guest

Meanwhile /hiddenCloset/ produced an MO disk with one more Vigenère message — but this one needed a key I didn't have yet, which the room hands you on the SSH side. An online identifier tried to call it a Hill cipher; that's wrong (Hill uses a numeric matrix and destroys word spacing). The preserved structure plus a supplied keyword pointed back to Vigenère:

# MO disk ciphertext, Vigenère key = albert (found via SSH)
wpbwbxr wpkzg pltwnhro, txrks_xfqsxrd_bvv_fy_rvmexa_ajk
weasker login password, stars_members_are_my_guinea_pig

SSH access came together as: user umbrella_guest (from eagle_medal.txt), password T_virus_rules (the "wolf medal"):

$ ssh umbrella_guest@10.x.x.x      # pass: T_virus_rules

06Privilege escalation → root

Standard first move on a new shell — list everything, including hidden files:

$ ls -la
... .jailcell ...
$ cat .jailcell/chris.txt      # yields MO Disk 2

The second MO disk confirms albert as the cipher key (closing the loop on the /hiddenCloset/ message from section 05). With the operator login weasker recovered, the box plays out its Resident Evil cutscene — and the escalation itself is blunt: the account can re-auth to root with the same password.

$ sudo su
# same password -> root
# id
uid=0(root) gid=0(root) groups=0(root)

07Root cause & remediation

Secrets hidden by obfuscation
crests, ciphers, encoded creds		 Encoding is reversible with no key — it is not protection. Never store credentials in reachable content; use real secrets management and access control.
Credentials on FTP
images, keys, notes downloadable		 Lock down FTP (no chained-credential reuse, least privilege) and keep key material off shared services entirely.
Empty-passphrase steghide
a blank passphrase is no passphrase		 Steganography is obscurity, not control; protecting it with an empty passphrase adds nothing.
Password reuse to root
sudo su with the same password		 Enforce separation between user and privileged credentials; restrict sudo to specific commands, not a blanket su.

08Takeaways

Biohazard is a recognition drill dressed up as a mansion. The single most transferable habit it builds: identify a blob by its alphabet and structure before you try to decode it, and re-identify at every layer. Caps + 2–7 is Base32; mixed case minus 0/O/I/l is Base58; preserved word spacing is a keyed cipher; a hash-identifier failing usually means it's not a hash at all.

The real-world echo is bigger than the theme suggests: hardcoded, encoded credentials sitting in apps, configs, and firmware are everywhere, and teams routinely mistake "it's Base64'd" for "it's secure." This box is that mistake, gamified. Next time I'd move faster on two things — trying an empty steghide passphrase first, and trusting the alphabet over an auto-identifier's guess.
